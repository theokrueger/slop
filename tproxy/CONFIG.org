#+title: tproxy configuration
#+description: Configuration reference for tproxy

* File location

Default: =~/.config/tproxy.yaml= (or =$XDG_CONFIG_HOME/tproxy.yaml=). Override
with =--config FILE= or =-c FILE=.

The file is YAML and is rewritten by =tproxy useradd= and =tproxy modeladd=;
comments and formatting are not preserved. Create it once:

#+begin_src sh
mkdir -p "${XDG_CONFIG_HOME:-$HOME/.config}"
touch "${XDG_CONFIG_HOME:-$HOME/.config}/tproxy.yaml"
#+end_src

* Example

#+begin_src yaml
server:
  host: "127.0.0.1"
  port: "8001"

models:
  "my-model":
    endpoint: "https://api.example.com/v1"
    api_key: "upstream-key"
    name: "My Model"
    context_window: 128000
    max_tokens: 16384

users:
  me: "sk-..."
#+end_src

* Server

| Field                     | Default     | Description                            |
|---------------------------+-------------+----------------------------------------|
| =host=                    | =127.0.0.1= | Bind address.                          |
| =port=                    | ="8001"=    | Bind port.                             |
| =log=                     | unset       | Append log file; stdout when omitted.  |
| =rate_limit=              | =100=       | Requests/minute per user.              |
| =max_concurrency=         | =128=       | In-flight requests before =503=.       |
| =allow_insecure_upstream= | =false=     | Allow remote plaintext HTTP upstreams. |

A =rate_limit= of =0= disables the per-user limiter. Rate limits use in-memory
token buckets.

Config and log files are written with mode =0600=. tproxy warns if the config
is group/world-accessible.

* Models

Keys under =models:= are client-facing aliases. Clients send the alias in the
JSON =model= field.

| Field            | Default    | Description                                    |
|------------------+------------+------------------------------------------------|
| =endpoint=       | required   | Upstream API prefix, normally ending in =/v1=. |
| =modelname=      | alias      | Model name sent upstream.                      |
| =api_key=        | unset      | Upstream bearer token.                         |
| =name=           | alias      | Display name returned by =GET /v1/models=.     |
| =context_window= | =128000=   | Context window in tokens.                      |
| =max_tokens=     | =16384=    | Maximum output tokens.                         |
| =reasoning=      | =false=    | Model supports reasoning.                      |
| =input=          | =["text"]= | Inputs: =text= and/or =image=.                 |
| =cost=           | zero       | Price per million tokens.                      |

When set, =modelname=, =name=, and =api_key= must be non-empty. Cost fields
are =input=, =output=, =cache_read=, and =cache_write=.
=/v1/chat/completions= is forwarded to =ENDPOINT/chat/completions=; the =/v1=
prefix is stripped and query strings are kept. Endpoints must use HTTP or
HTTPS, must not contain credentials, and remote plaintext HTTP requires
=allow_insecure_upstream: true=.

Model metadata is served by =GET /v1/models=. The model list is built at
startup; restart tproxy after changing models.

* Users

=users= maps names to API keys. Clients send =Authorization: Bearer <key>=.
Keys must be non-empty and must not contain whitespace. Generate keys with
=tproxy useradd alice=.

Keys and upstream API keys are stored in plaintext; keep the config private.
Short keys produce a startup warning.

* Usage data

=GET /= serves a public dashboard of hourly request counts per user and model;
=GET /usage.json= serves the same data as JSON. Data is kept for 30 days in
=$XDG_DATA_HOME/tproxy_usage.json=, with an append-only
=$XDG_DATA_HOME/tproxy_usage.json.log= journal (default
=~/.local/share/). The journal is flushed every 5 minutes and compacted
periodically and on shutdown. Both files use mode =0600=. Neither endpoint
requires authentication.

* Pi extension

The extension at [[file:extensions/pi.ts][extensions/pi.ts]] registers a Pi provider named
=tproxy=. It has no environment-variable configuration and defaults to
=http://127.0.0.1:8001/v1=. Model IDs, names, capabilities, limits, and costs
come from =GET /v1/models= through Pi's =refreshModels= hook.

Authenticate with =/login tproxy=, then open =/model= once to trigger
discovery.

To override the endpoint or provide the key in Pi, add a provider entry to
=models.json=:

#+begin_src json
{
  "providers": {
    "tproxy": {
      "baseUrl": "http://127.0.0.1:8001/v1",
      "apiKey": "sk-...",
      "api": "openai-completions"
    }
  }
}
#+end_src

Model metadata is always read from tproxy; the extension has no hardcoded
model IDs, limits, capabilities, or costs.
